# Magnetism Lab

Open `gdevelop/game.json` in GDevelop, select TrainingGrounds and Preview. For the browser, open `prototype/index.html` with its extracted folder intact. From the home hub tap **Magnetism Lab** at the former magnet station, or **Places → Magnetism Lab**. Tap a bench to approach automatically. **Home hub** exits; PIP → Return home also returns directly.

Four repeatable experiments:

- **Push and pull:** select N/S or N/N facing poles; the diagram shows inward or outward arrows. Polarity labels accompany the symbols.
- **Material detective:** compare an iron washer, wood, copper and aluminium. Only iron shows strong attraction in this ordinary-magnet model. Electrical conductivity does not imply strong magnetic attraction.
- **Coil lab / Switchable electromagnet:** open/close a virtual circuit and compare one or three turns at the same assumed current. The diagrams change turns and washer positions. OFF releases the washers. One/three lifted washers are illustrative results, not measured predictions.
- **Generator:** move a magnet in or out of a coil, or hold it still. The static result diagram represents a transient voltage pulse; reversing movement reverses its sign. The lamp depicts either polarity using an idealized nonpolar lamp. It does not model a permanently lit lamp after motion stops.

No timer, grades, rapid tapping, dragging, purchases or resource costs. Every astronaut can use every experiment. Reset is optional. Large native and HTML buttons use the existing keyboard, switch/controller navigation, narration, captions and display supports. SVGs have a textual result alternative in the browser; diagrams do not rely on suit colors. Native experiments fit the six-button menu limit.

An actual experiment choice records a reusable **My Experiments** entry. Merely opening a bench does not. Revisit routes back to the bench, and trial flags persist through existing local saves. Per-bench control choices reset on reopening; the journal retains participation, not every experimental configuration.

## Implementation

`prototype/src/magnetism.js` holds configurable content, pure experiment rules and original diagrams. `open-spaces.js` supplies the single-screen room and benches using the existing world renderer; `data.js`/`zones.js` connect the home portal. `main.js` and `gdevelop/src/magnetism.js` present the shared rules. `journal.js` records trials; the native profile loader accepts the new trial IDs. Build scripts regenerate `prototype/game.js` and `gdevelop/game.json`. Original native PNGs are generated by `gdevelop/scripts/magnetism-assets.mjs` using optional Sharp (`JACC_SHARP_PATH`). No runtime dependency was added.

Build with `node prototype/scripts/build.mjs` and `node gdevelop/build.mjs`.

## Validation and limits

52 shared tests pass, including scientific outcomes, circuit/turn changes, induction reversal/stillness, reset, station reachability, menu limits and journal criteria. The GDevelop API harness tests all four experiments, diagram changes, saved trials, reset, journal and two-way hub travel alongside existing gameplay. Chromium mouse/touch tests cover all four experiments, minimum 60px action buttons, journal revisit and reload. Core browser regression tests also cover retained exploration and menus.

Run `node --test prototype/tests/*.test.js`, `node gdevelop/tests/native.cjs`, `node prototype/tests/magnetism-browser.cjs` and `node prototype/tests/browser.cjs` (browser checks require Playwright and Chromium).

These are qualitative educational models with static outcome diagrams, not quantitative field/electrical simulations. There is no physical electrical equipment tutorial. Art remains provisional; GDevelop editor rendering, real iPad/adaptive hardware, screen readers and child testing remain outstanding. Next: test the lab with children on target devices, then add field-line/compass and motor investigations.
