It includes ages 5–16, unplugged exercises, Scratch/ScratchJr, Python, webpages, charting, bots, classification and games. Its heading/review date and byline update date differ; those dates and the article's effectiveness claims have not been independently verified. No external course, account integration or third-party code is being imported.

This is a proposed activity design, not an implemented programming system. Use a **Coding & Robot Logic Bench in the GSEINHQ science lab**, with robot/automation links to engineering, farming and future habitats. ## One-action programming workflow

Select a command → select its slot → preview → Run or Step → observe → change → repeat. Provide a separate large rotation/parameter button rather than requiring dragging, chords or precise pointing. Offer Undo, Reset and an undoable PIP demonstration. Event programs use selectable objects and pictorial conditions, such as “when the button is tapped → PIP waves.”

Begin with sequences. Offer loops, conditions, variables and data views as optional layers, without age labels that limit access. Include a clear stop control for running programs; repeated/looping demonstrations must remain bounded and interruptible. No failure penalty, elapsed-time score or required quiz.

Future scripting should use a small validated command schema, not arbitrary JavaScript execution or external code downloads. A child's program must not disable AAC, pause, settings, help or return-home controls. Multiple story events must not require simultaneous physical actions.

## Important teaching distinctions

- Digital binary representations use defined encodings. A name is not universally one fixed-width byte per character. ASCII can illustrate a limited character set; full player names, including accented characters, require an explicit suitable encoding such as UTF-8. Always label the representation and avoid requiring English-only names.
- A sequence, an event, a loop and a condition have different roles. Use visible execution highlighting and optional narration rather than presenting colored tiles without meaning.
- Sorting algorithms have different comparison/swap behavior; do not imply the fewest moves necessarily identifies bubble sort or the best algorithm.
- Graphs must distinguish actual saved observations, simulated data and illustrative examples. Do not invent experimental measurements or label a layout editor as real HTML coding.
- A machine-learning demonstration requires a defined trained model and distinct test examples. Recognition can be wrong; limited samples do not establish general understanding or a reliable scientific identification tool.
- Keyboard text coding and external platforms can be optional later learning paths. They must not become prerequisites for the core ages 6–10, one-finger experience.

## First prototypes and access

Suggested first prototypes: PIP Route Builder, Buddy Play Lab and Discovery Graphs, followed by sequences/loops and Signal Bracelet. Start by making one small visible response; sessions can end at any time and save progress, with no fixed duration requirement.

Retain adaptive switches/controller inputs, screen-reader-friendly command names, optional narration/captions, large targets, shapes/text alongside colors and AAC access throughout. Guided play offers one optional step; exploration lets children return to a favorite activity indefinitely. No new live AI assistant or external service is implied by this plan. Scientific/content review, actual assistive hardware testing and child usability testing remain necessary.
